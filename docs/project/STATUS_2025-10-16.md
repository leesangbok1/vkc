### ⚠️ Google 콘솔 ‘홈페이지 등록’/원본 오류 이슈 가이드
- 테스트 모드에서는 App domain(홈페이지/Privacy/Terms) 필드를 비워두어도 됩니다. 127.0.0.1/localhost 도메인은 승인된 도메인으로 추가/검증할 수 없습니다.
- 오류 메시지 예: “Homepage URL must be on an authorized domain” → 테스트 단계에서는 해당 필드 제거(비움)로 진행하세요.
- 프로덕션 전환 시(퍼블리시): 실제 소유한 도메인(예: vercel 배포 도메인)을 Search Console로 소유권 검증 후 App domain에 추가하고 Homepage/Privacy/Terms를 HTTPS로 설정합니다.
- Redirect URI는 Supabase 콜백만 Google에 등록합니다. 로컬 앱 URL(`/auth/callback`)은 Google이 아닌 Supabase가 내부적으로 처리합니다.
- `redirect_uri_mismatch` 발생 시, Google에 등록된 리디렉션 URI가 정확히 `https://<프로젝트-ref>.supabase.co/auth/v1/callback` 인지 확인하세요(트레일링 슬래시/철자 주의).
- `localhost` 대신 `127.0.0.1` 사용 권장: Google OAuth 개발환경 제약으로 팝업/리다이렉션 문제가 줄어듭니다.
- “잘못된 원본: 공개 최상위 도메인으로 끝나야 합니다” 오류는 App domain/Authorized domains 필드에 IP를 입력했을 때 발생합니다. 테스트 모드에서는 비워두세요.
- “올바르지 않은 출처: URI는 경로를 포함하거나 '/'로 끝날 수 없습니다” 오류는 `http://127.0.0.1:3008/`처럼 슬래시가 붙었거나 경로가 포함된 경우입니다. `http://127.0.0.1:3008`처럼 슬래시 없이 입력하세요.
